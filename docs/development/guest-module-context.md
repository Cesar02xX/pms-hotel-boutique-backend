# Guest Module Context

## GitHub Ticket

Issue #8: `[Backend] Implementar modulo de gestion de huespedes`

Branch: `feature/guests`

Target PR base: `develop`

## Scope

Implemented the backend API contract needed by the frontend mock guest service:

| Method | Endpoint | Purpose |
| --- | --- | --- |
| GET | `/api/v1/guests` | List guests |
| GET | `/api/v1/guests/{id}` | Get guest by UUID |
| POST | `/api/v1/guests` | Create guest |
| PUT | `/api/v1/guests/{id}` | Update guest |

DELETE remains out of scope.

## Important Decisions

- The existing `Guest` entity and `GuestRepository` are reused.
- The API uses real UUID values generated by JPA/backend, not frontend mock IDs like `GST-001`.
- `createdAt` and `updatedAt` are controlled by the backend.
- Request/response DTOs isolate clients from the JPA entity.
- `firstName` and `lastName` are required for create and update.
- `email` is optional but must be syntactically valid when present.
- `documentType` uses the existing `DocumentType` enum only.
- Invalid UUID route values and invalid enum/body payloads rely on the shared `GlobalExceptionHandler` 400 behavior already present in `develop`.

## Out Of Scope

No changes were made for reservations, rooms, rates, folios, payments, deposits, inventory, cash, auth flows or Liquibase schema changes.
